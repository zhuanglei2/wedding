# 婚礼动画完整需求与重跑交接

保存日期：2026-09-09。用户要求完整保留，方便明天继续；本文件不是生成提示词，
不能将所有内容一次性塞进4秒生成任务。若后续用户改动，新增版本并记录明确差异。

## 1. 最终想要的体验（不能因小样简化而丢失）

- 打开网页首先看到正式红色婚礼请柬，不增加另一层开屏封面或开门页面。
- 点击首屏即可触发进入下一页，不出现“翻开我们的故事”兜底按钮或额外确认步骤。
- 星星人从画面外飞来，接近请柬右侧自由边，带着纸张拉开；不是两张静态贴图一起平移。
- 正式红请柬作为有厚度的卡纸向外翻开，露出第二页原始婚纱照片。颜色变化有过渡，不突兀硬切。
- 拉开后男孩松手，先悬停等待女孩；女孩赶上，两人牵手后一起飞走，不能男孩独自先离开。
- 飞行时有细腻的金色星星拖尾；拖尾跟随实际运动路径，减速时收敛、结束后自然消失。
- 后续页面内容仍以用户之后的决定为准，不为了制作转场擅自定稿整站。

## 2. 人物与动作

- 使用用户选择的泡泡玛特星星人婚礼装扮，始终恰好男孩和女孩两个角色。
- 保持角色形象、帽子、发型、衣服颜色、衣领、女孩头纱、花束、完整裙身；不增肢体，不换脸换衣。
- 圆手套保持玩偶造型，不要求出现五根写实手指。抓握靠手套包边、手腕角度与肘肩变化表达。
- 眼神可见地看向抓点、看向同伴；头部、肩膀、身体、衣摆头纱有协调反应和轻微时间差。
- 不只移动瞳孔，不拆坏脖子，不把衣服从身体上分离；不得再次出现领口缺失、脸部透明洞、断肢。
- 飞行具有准备、加速、转向、减速与悬停；身体姿态跟随速度，衣摆头纱略滞后，避免机械晃动。
- 男孩先看抓点、稳住圆手套，再通过手肘和肩膀表现发力；纸张随后响应，手不能滑动或突然换边。
- 女孩略晚响应男孩。拉动阶段主要看着男孩、持花轻随，不向上突然弹起，也不同时强行加抓纸动作。
- 等待与牵手阶段两人有互看、靠近、接触后共同离开的节奏；不得手没松开纸边就飞走。
- 人物要小巧、不抢请柬主体；以当前审核参考比例为基础，不因为看不清抓握就整体放大。
- 头、帽子、手、裙摆不在关键动作中出框；不让角色压住姓名或重要文案作为永久初始状态。

## 3. 纸张、方向与视觉

- 正式卡面就是已确认的红金请柬，保留金色字、牡丹纹理和光影，不重新设计或绘制真实内容。
- 左侧为固定翻页轴，右侧为可拉动自由边，卡面向观看者方向打开，右自由边向画面左侧移动。
- 进场可从右上方向接近右侧抓点；抓点高度需结合手机视口与完整角色安全区域确定，
  不把实验图上的像素坐标直接当成最终页面位置，也不锁死为掀右上角柔软纸角。
- 表现厚卡的直边、薄切边、整体透视和接触阴影；不做塑料布、软纸卷角、S形波浪、撕裂或大面积白色背面。
- 厚度有质感但不能像门板一样生硬。正文、照片使用同一受控卡面变换，不逐行挤压图像。
- 不能为了露出纸边给正式请柬永久增加米色留白、外围框或底部红色色块。
- 技术参考帧的灰蓝外背景仅为生成工作区，不是最终页面新增边框。
- 最终需要完整打开并退场、衔接真实第二页；4秒测试中只开40–45°不等于这个终局已完成。

## 4. 真实照片与页面保护（最高优先级）

- 不把有真实婚纱照的完整请柬上传视频生成模型。此前实际发生过真实照片人物跟着动的问题。
- 生成只接收空白红卡与卡通星星人。正式请柬照片、文字独立保留，由本地/网页合成控制。
- 真实新人五官、发型、服装、颜色、姿态、朝向、人数保持原样；不换脸、不换衣、不重绘或增人。
- 不动原图文件。全卡透视、显示裁切与文件修改必须区分；不通过扭曲真实照片迎合错误AI纸面。
- 不把“空白卡生成成功”当作“能无缝贴上真实请柬”；人物遮罩、同一抓点、前后遮挡、整卡几何均需实测。
- 首屏长请柬按完整构图显示，不强行压扁成9:16。已认可的压缩优化与重新构图是两件不同的事。
- 已确认婚礼信息：庄磊、吴郁；2026年10月6日，晚宴；浙江省宁海西子国际大酒店；
  宁波市宁海县跃龙街道外环东路8号。没有已确认具体几点，不擅自添加。
- “庄磊与吴郁 敬邀”之前已要求去掉，不恢复；正式图上的其余文案不随动画实验改写。

## 5. 手机与交互验收

- 优先真实手机与微信环境，不以桌面截图代替手机验证。
- 点击只触发一次；动画期间快速滑动、重复点击、切后台再回来不能卡住、重入或残留遮罩。
- 明确管理滚动锁定/恢复和转场结束状态，不让滚动位置与视频时间互相拉扯。
- 视频未加载、播放被拦截、网络慢或动画失败时仍能进入下一页；不能卡死在动画层。
  降级可简洁淡出/直接进入，但不要新增用户已拒绝的兜底文案按钮。
- 不出现底部空白红块、接缝、米色永久留边、两层重影或结束后的一条红边。
- 照片与文字加载清晰；首屏优先，后续媒体可延后加载。注意微信缓存，部署后验证实际文件。

## 6. 分段制作方案：最终需求不变，每次只验证一件事

### 下一次4秒动作小样

- 起始已握住右侧纸边：看抓点 → 手腕/肘肩预备发力 → 一次连续左拉 → 稳住保持。
- 女孩稍晚跟随，身体与头纱轻微响应。卡面仅约40–45°，目标是验证动作，不是完整开卡。
- 最后约0.5秒留稳定抓握状态供检查。不要把松手、牵手、飞走、拖尾同时塞进去。
- 这是导演节奏要求，不是模型能精确执行的逐帧时间承诺。

### 后续段（尚未完成，不能遗漏）

- 基于实际合格首段的尾帧衔接，不用假想尾帧：继续打开 → 松手 → 男孩等待 → 女孩靠近 → 牵手一起飞走。
- 星星拖尾可在后期独立控制，避免生成模型同时处理太多要素；不能因此从最终需求删除。
- 两段保持角色位置、大小、方向、服饰与光影，检查接点前后连续帧，不用重影交叉淡化隐藏跳变。
- 第一段尚未验收时，不宣称第二段能无缝拼接。先解决实际素材，再接入正式网页。
