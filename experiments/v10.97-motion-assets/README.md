# V10.97 — 原素材整理与下一次动作补充包

本版不是新生成的动画。只做本地素材整理、回读验证、下一次生成草案；没有上传、扣费、部署。
沿用 HyperFrames 的现有项目检查路线及 media-use 的本地媒体处理、素材登记流程。

## 一个重要纠正

前版用“扣指”描述验收不准确：角色是圆手套造型，不应为了抓握长出人类手指。
正确目标是：手套端部包住厚卡边缘、手腕与手肘有变化、肩膀先发力、卡随后响应，
并保留完整衣领和手套造型。圆手套不需要写实手指也可以表现抓握。

## 已整理的实际素材

- `boy-rgba.mkv` / `girl-rgba.mkv`：97 帧独立人物层，FFV1 BGRA 无损中间文件，
  用于合成，不是浏览器直接播放格式。每帧四通道逐像素回读核对通过。
- `source-poses.jpg`：实际源帧 0、18、24、36、60、96 的姿态，不是生成的新分镜。
- `reference-source-f024.png`：源视频第24帧（1秒），未裁切、未重绘；
  男孩转向纸边，另一只手收至身体前方，比正面摊手更适合作为起始姿态候选。
  这帧仍不代表已有合格的包边抓握，不能直接视作最终首帧定稿。
- `PROMPT-DRAFT.txt`：仅针对一次拉动的待审草案，未提交，也未承诺能成功。

无损四通道保存仅说明没有增加存储损失，不说明原来的抠像边界完美。
头纱细边的原有轻微色边仍须在实际背景和手机尺寸下检查。

## 现有动作能用在哪里

| 源片范围 | 观察 | 适用范围 / 限制 |
| --- | --- | --- |
| 0–0.75秒 | 男孩正面转向纸边，空闲手向身体前方收回 | 可作为注意、准备的小动作；不是完整拉动 |
| 0.75–1.25秒 | 男孩侧身看接触处，抬起手仍在边缘 | 起始姿态候选；未看到充分的包边、肩肘发力 |
| 1.5–4秒 | 男孩转回正面，空闲手展开；女孩逐渐上移 | 可筛选悬停姿态；与持续左拉方向不符，不直接拼作拉动或松手 |

以上是选取关键帧的定性观察，不是每个关节的逐帧运动学测量。

## 下一次只补一个动作

四秒目标分配是制作要求，不是可保证的模型精确时间控制：

1. 约前0.7秒：看向抓点，圆手套稳定包边；手肘收回、肩膀预备发力。
2. 约0.7–3.3秒：一次连续拉动，先身体受力，再带动卡片；女孩略晚跟随，不向上窜。
3. 最后约0.7秒：保持抓握、自然减速，不松手、不飞走。

删除了松手、等待、牵手、飞走、拖尾等竞争指令。它们仍属于后续待补内容，
本次不声称已经有完整动画或已解决两段视频衔接。

## 上传与验收门槛

- 当前 `submitted=false`。提交前重新核对账号余额、当次费用、4秒时长是否可选，
  不用历史余额推断现在可用额度。需用户明确同意本次消耗，禁止自动重试。
- 不上传真实请柬、婚纱照或文字。候选帧只有原空白红卡与两个卡通角色。
- 候选首帧需先检查：手套在原纸边、完整衣领和裙身、人物比例、边缘余量。
  它仍缺少已确认的包边形状，若预览不能补足，则先修首帧，不直接提交碰运气。
- 验收看连续手腕/手肘/肩膀变化与同一抓点，而不是只看手贴纸边或卡片动了。
- 角色、服饰变形或换手，关键接触长期遮挡，女孩上窜、手套长出写实手指，直接否决。
- 原生成卡只作交互参考，不用于覆盖真实请柬。分离人物后仍需做纸边跟踪、遮挡、
  前后景合成实测；单靠参考角度40–45°不能保证适配后续完整180°翻页。
- 本版不额外改变角色大小。需要新动作素材，不需要再把既有动作整体放大。

## 重现

输入：V10.95 的已下载原视频，V10.96 的两个角色遮罩序列。
先用 V10.96 的 `matte.py <work>/mattes` 重建遮罩，再执行 `prepare.py <work>`。
依赖路径沿用已有临时 OpenCV/NumPy/FFmpeg 环境；中间人物层已冻结在本版本中，
所以后续合成不再依赖临时 PNG 序列仍存在。
