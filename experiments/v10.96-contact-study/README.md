## 实际改动

1. 用源视频引导的 GrabCut 代替单纯红色筛选；保护实际肤色轮廓内部，补回被误抠的嘴边。
   只改变 alpha，不重绘人物、不修改源视频 RGB。97 帧的保护区域均保持不透明。
2. 男孩与女孩单独提取；女孩仅保留自身连通轮廓，去掉重叠选区误带入的男孩鞋子。
   男孩裤腿之间的红色背景空隙单独排除，轮廓外不再扩散红底像素。
3. 男孩围绕手套锚点做小幅整体倾斜，纸张在 0.65 秒后响应。女孩的跟随路径延后 0.18 秒。
   保留源视频自带动作，不重新拆头、脖子、衣服或肢体；此倾斜不是新生成的关节动作。
4. 增加局部接触阴影，以及纸边经过手套外侧的细微遮挡提示。真实封面整体走同一透视变换。

使用动画技能的先接触后响应、缓起缓停原则，以及 media-use 的本地媒体预处理流程。
角色不再绑定为一个共同平移层，但仍不能把这个改动称为完整自然表演。

## 验收结论

技术检查通过；最终动作质量未通过。

- 两个视频均完整解码 78 帧、24fps。封面、第二张照片和源视频的 SHA256 未变化。
- 卡面 0.65 秒前保持闭合，之后角度单调增加，2.05 秒达到 48° 并保持。
- 已检查最终深浅底五组关键帧，以及六组接触放大图：上一版嘴边穿孔已修复，
  女孩分层中的游离鞋子已消除，所检查帧的衣领与裙身没有出现之前那种大片丢失。
  头纱细边仍有轻微色边；没有人工逐像素认证所有97帧边界。
- 保护区域不透明与锚点误差小，只证明计算约束，不证明全身每个像素都正确或手指真的握住纸。
- 手部仍是源素材中的伸手姿态，局部前后遮挡只增加接触提示；缺少扣指、肩肘发力和松手。
  拒绝把这版标记为“抓握自然”“完整拉开”或可直接上线。
- 女孩具有单独时间和路径，但大部分变化仍来自原视频和整身变换，尚不是自然协作动作。
- 初始即有角色，缺少完整进场；这版不演示打开到底、等待、牵手、飞走、拖尾或网页衔接。

## 下一步素材缺口（不在本次生成）

现有视频可以用于短暂悬停、转头、小幅身体动作。不能从中可靠剪出完整抓握、
发力拉开、松手的连贯过程。继续叠加整身旋转不能补出不存在的手部动作。
后续若补素材，必须围绕同一纸边明确取得“握持—肩肘带动—拉动保持—松手”的
连续角色动作，并为女孩取得独立跟随姿态；先检查素材，再增加飞走剧情。
真实请柬照片与文字仍留在独立可控层，不再送给视频模型。

## 重现

在 wedding 仓库下，用已安装 OpenCV、NumPy、imageio-ffmpeg 的 Python 执行：

```sh
python3 experiments/v10.96-contact-study/matte.py /private/tmp/your-work/mattes
python3 experiments/v10.96-contact-study/render_contact.py /private/tmp/your-work
```

当前脚本使用已有临时依赖目录 `/private/tmp/wedding-v1088.TQDAlk/libs`，
及 V10.95 的卡面几何函数和源视频。若临时依赖过期，需安装依赖并更新路径；
源素材和结果在版本目录中保留，不依赖 PixVerse 在线链接继续有效。

`source_grid.py <tmp-dir>` 输出带坐标的原视频头部检查图，用于审查保护范围。
