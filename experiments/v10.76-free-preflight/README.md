## 真实请柬衔接：推进了什么

已验证的是“有准确纸面网格与可用透明人物层时，原请柬能够作为纹理随纸面变化，并与真实下层素材合成”。

这次不是浏览器页面截图，而是原生离线图像合成测试：不访问被浏览器阻止的页面，也不绕过浏览器策略。已查看实际生成的静态测试画面。最初的独立三角裁切有明显分块细缝，改用共享边界的软件栅格化后重跑并再次查看。

在测试分辨率下，首帧像素与直接显示原请柬一致；末帧像素与同一缩放规则下的原第二层一致。这里的“像素一致”比较的是同一离线渲染规则，不是与手机浏览器截图比较。

这些不是完成线上衔接的证明。仍然缺少：

1. 真实视频中的人物透明遮罩（尤其头纱、手指与纸边接触处）。
2. 真实视频逐帧的纸面变形跟踪。合成器目前使用程序提供的网格，不能凭空把不透明 MP4 变成分层资产。
3. 真实角色的自然动作、完整服装、可信抓纸/牵手。
4. 网页触发时视口与滚动位置映射、视频播放和滑动恢复、微信手机验收。

不以源文件未改、数学测试通过或这些静态画面替代上述四项。没有将此流程标为“真实视频接入问题已解决”。

## 运行

使用可用的 Node.js 执行 composite.cjs。它默认读取当前工作环境已有的 @napi-rs/canvas；其他环境通过 WEDDING_CANVAS_PACKAGE 指向本机已安装包。没有自动安装、联网或调用生成服务。

脚本只写入本目录 output/，不会写原素材文件。输出静态 PNG 与测试 JSON，不生成声称为“完整动画”的视频。

## 积分使用判断

免费准备能排除排版、提示词与确定性合成算法的问题，但无法保证生成模型会给出可跟踪的纸面和可分离的人物。现阶段不主动花积分生成测试片，也不把剩余积分视为足够一次成片。

完整拉纸动作没有从诉求中删掉。之后若要提交完整试做，仍需先核对当前实际费用，并明确接受一次输出可能无法可靠接入的风险；不自动拆成多次尝试。
