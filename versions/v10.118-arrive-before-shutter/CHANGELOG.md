# V10.118 · 到位后再按快门

基于 V10.117，独立版本；旧版保留。本版只调整角色飞向相机与操作快门的动作，不改原照、排版或部署入口。

## 原因

V10.117 将松手后的角色直接插值到按键姿态，飞行、侧身和伸手用了同一进度。结果是角色还在移动，手已摆出按键动作，缺少可辨认的到位与操作过程。

## 调整

- 松开纸张后先在 300ms 内收回手臂，再用身体倾斜、上身跟随、一次收腿与衣摆滞后表现飞行；头/领口仍是一整块原素材，不重新拆颈部。
- 男孩在第二段 500ms 到达快门旁，女孩沿独立右侧弧线于 650ms 到位。
- 男孩停稳 220ms 后开始侧身；1020ms 才伸手，1380ms 触到按钮，1450ms 开始按压，随后沿用镜头与屏幕闪光。
- 飞行路径与操作姿态分离：飞行途中操作手保持收拢；进入操作阶段后身体中心固定，不靠整张角色贴图平移去碰按钮。
- 女孩保持放松的双臂与注视/眨眼，不模仿男孩按按钮。拍照后牵手、打印、放大和文案时序不变。
- 保留 V10.117 一次播放终态：返回滚动不再出现角色；无重播按钮。

## 验证

五组离线检查全部通过：

1. `test-camera-story.cjs`：原照摘要、引用、24 种尺寸、闪光/打印/放大/文字时序。
2. `test-runtime.cjs`：拍立得控制器启动、结束与中断。
3. `test-handoff-math.cjs`：两段位置和速度连续、分离路线、抓纸和快门接触、拍后牵手。
4. `test-opening-runtime.cjs`：两控制器联合运行，44 次往返滚动、14 个阶段中断场景和 12 个点击位置。
5. `test-approach-poses.cjs`：所有飞行帧手臂保持收拢、到位后才伸手、实际生产角色绘制变换（不是未使用的姿态字段）确实改变上身和手臂。

绘制变换和 DOM 替身测试不是浏览器像素/微信真机视觉验收；本轮未执行浏览器交互或截图。素材仍是二维分层角色，并非新增三维模型或 AI 视频。
