# V10.213 · 微信就绪与首次交互时序修正

基于已部署 V10.212。用户反馈微信无法自动播放，但点击“开启音乐”可正常出声。

## 已确认的问题

V10.212 会在封面未完成加载/解码/显示时，直接跳过真实微信桥就绪回调和首次全页触摸/点击。离线复现：`coverReady=false` 且桥对象存在时，发送就绪回调后 `audio.play()` 调用次数仍为 0。

普通首屏就绪尝试还会仅因桥对象存在就标记桥机会已使用，导致之后实际就绪回调无法重试。这是已复现的代码时序缺陷，不能单凭此断定用户真机失败完全由它引起。

## 修改

- 真实微信就绪回调内直接尝试播放，不等待图片和异步帧；不伪造桥事件、不调用无关原生接口。
- 真实首次触摸/点击也不再被首屏素材状态拦住。页面仍尊重浏览器的播放决定，被拒绝就显示小按钮。
- 普通首屏就绪尝试不预先消耗微信就绪机会；后台恢复不重复正在等待的播放请求。
- 非交互的一般自动尝试仍等首屏显示完成；因此微信回调或有效点击可能比素材加载更早发起播放。
- 仍从 50 秒开始、尊重手动暂停、不重置已播放进度。HTML、相片、纸张、动画、歌词与时间轴都未修改。

## 验证与状态

音乐、实际首屏就绪模块联合模拟、照片一致性及资源检查通过。新增覆盖慢网封面、真实回调先到、桥对象已存在、首次交互先到、重复通知、手动暂停和拒绝后点击恢复。
